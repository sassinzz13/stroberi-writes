# Global Codex Memory Rules

Add this section to `~/.codex/AGENTS.md` after your existing full-stack engineering mentor instructions.

- At the start of work inside a project, look for project `AGENTS.md` and `.codex-memory/INDEX.md`.
- Read the project's current state and only task-relevant memory first; avoid unnecessary whole-repository scans.
- Treat memory as a navigation aid, never as authoritative proof of current code behavior.
- Verify the current Git state and inspect relevant source before editing or making claims.
- After meaningful work, maintain concise, accurate memory of user requests, implemented changes, architectural decisions, affected paths/symbols, actual test results, and next steps.
- Explicitly label planned, implemented, tested, blocked, and unverified work. Never fabricate completion or tests.
- Keep notes easy to search and avoid duplicate, stale, or excessively long entries.
- Never store credentials or sensitive secrets.
- Always explain what, why, how, internal mechanics, and verification in accessible language.
